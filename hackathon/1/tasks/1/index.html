VectorAdd

One-dimensional vector addition with FP32 arithmetic and a final cast to the input dtype

Operator definition

z = x + y

Interface

vector_add(Tensor x, Tensor y) -> Tensor z

Data ranges

x,y,z:[L]; L=1..4294967295

Single-die stress scale

One physical die only (nominal 64 GiB HBM). Functional cases remain small and exhaustive; the independent three-tier stress suite exercises large bandwidth, compute and random-access workloads. Input + output tensors must total <=48 GiB, candidate workspace <=8 GiB; reserve >=8 GiB for runtime. Shape bounds are not a Cartesian guarantee: combinations exceeding the byte budget are invalid. Pressure correctness compares complete offline binary standards outside timing. Public stress runs are debugging only; formal pressure scoring starts only after all functional checks pass. Host wall time includes CPU work, dispatch and device synchronization, not only kernel time. No other die or CPU computation fallback.

Value ranges and coverage

FP16: [-32000, 32000]; BF16/FP32: [-1048576, 1048576]. Finite inputs only. Coverage includes zero, small magnitudes down to 2^-12, large magnitudes, positive/negative-only data, mixed scales, sparse data and representable boundaries. Task-specific tests also cover cancellation, BF16 ties and saturated softmax. NaN/Inf are excluded; subnormal preservation is not required. Not every tensor must span the entire range.

Parameters

Inputs

  • x: ['float16', 'bfloat16', 'float32'] — Input vector x
  • y: ['float16', 'bfloat16', 'float32'] — Vector with the same shape and dtype as x

Outputs

  • z: ['float16', 'bfloat16', 'float32'] — Sum of the two input vectors

Attrs

    Numerical and implementation requirements

    Inputs are contiguous, on the same card, and have identical shapes and dtypes. Finite values: FP16 in [-32000, 32000], BF16/FP32 in [-1048576, 1048576]. Output uses the input dtype and device. Broadcasting and in-place computation are not supported.

    Outputs must remain on the input device, be contiguous, leave all inputs unchanged, and not alias any input. One physical die only; using the sibling die or multi-card communication is prohibited. Core computation, data movement and conversions must use custom NPU kernels.
